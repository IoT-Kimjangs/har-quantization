# 실험 규약

실행 방식·환경 차이를 분리하고 같은 조건의 결과끼리 비교합니다. Mac과 Windows의 결과는 각각의 플랫폼 안에서 상대적 변화와 순위를 먼저 해석합니다.

## 조건

- 데이터: WISDM, PAMAP2
- 방식: Keras predict(), Keras model(x), TFLite FP32, FP16, INT8 동적, INT8 전체 정수
- 플랫폼: Mac ARM, Windows x86
- 스레드: 1스레드와 기본 설정을 별도 실행으로 기록
- 배치 1, 워밍업 50회, 측정 1,000회, seed 42
- WISDM 윈도우 80·stride 40, PAMAP2 윈도우 200·stride 100
- 논문 방식 재현은 80:20 분할을 기록하고, 피험자 단위 분할 실험은 별도로 구분

## 측정

Keras 두 방식은 `training=False`와 출력 완료 시점을 일치시킵니다. TFLite는 인터프리터 생성·텐서 할당·모델 로드를 반복 추론 시간과 분리합니다. delegate 종류와 실제 스레드 설정을 기록합니다. 전체 INT8은 대표 데이터 구성과 입출력 dtype·scale·zero-point를 남기고, 입력 양자화 및 출력 역양자화를 타이밍에 포함했는지 명시합니다.

중앙값·p95와 개별 반복의 원시 지연시간을 보관합니다. 피크 RSS는 프로세스·런타임을 포함한 값이며 모델 파일 크기와 다릅니다. 모델별 독립 프로세스에서 측정해 이전 실행의 메모리 피크가 섞이지 않도록 합니다. 전원 연결·절전 설정·백그라운드 작업 조건을 기록합니다.

정확도와 Macro-F1은 실제 테스트셋으로 계산합니다. 무작위 입력은 지연시간 사전 점검에만 사용하고 정확도 결과로 보고하지 않습니다. 저장 모델이 실제로 어떤 분할에 학습됐는지 알 수 없으면 정확도 재현의 한계로 적습니다.

## 효과 분리

| 비교 | 해석 |
| --- | --- |
| Keras predict() → Keras model(x) | 호출 방식의 영향 |
| Keras model(x) → TFLite FP32 | 런타임·변환의 영향 |
| TFLite FP32 → FP16·INT8 | 같은 런타임에서 양자화의 영향 |

압축률은 `.keras` 기준과 TFLite FP32 기준을 따로 계산하고 기준 크기와 단위를 적습니다. 파라미터 수는 실제 사용 여부와 구분합니다. 노트북 2대의 결과를 전체 ARM/x86 또는 스마트워치의 일반적 성능으로 확대하지 않습니다.

## 결과 파일

`results/<날짜>-<플랫폼>-<실험명>/`에 환경 JSON, 의존성 목록, 요약 CSV, 반복별 CSV와 실행 메모를 둡니다. `results/summary-template.csv`는 헤더 양식이며 측정 결과가 아닙니다. 미측정 정확도는 빈칸으로 남기고 0으로 채우지 않습니다.
