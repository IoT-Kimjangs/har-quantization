# Windows 최종 결과 요약(보고서 초안)

## 실험 범위와 환경

WISDM과 PAMAP2 데이터를 사용해 Windows 11 x64 환경의 CPU에서 저장 모델을 평가하고, Keras 실행 경로와 TFLite 변환 및 양자화 실행 경로의 지연시간을 비교했다. 실행 환경은 Python 3.12.10, TensorFlow 2.21.0, Keras 3.13.2, LiteRT 2.3.0이다. 측정은 배치 크기 1, 워밍업 50회, 측정 1,000회로 수행했으며, 아래 지연시간은 반복 측정의 중앙값이다.

## 정확도 결과

| 데이터셋 | 평가 샘플 수 | FP32 정확도 | FP32 Macro-F1 | INT8 정확도 / Macro-F1 및 크기 |
| --- | ---: | ---: | ---: | --- |
| WISDM | 5,358 | 96.771% | 95.458% | 96.790% / 95.474%; 111.2 KiB |
| PAMAP2 | 494 | 97.368% | 96.736% | 97.368% / 96.736%; 315.9 KiB |

Windows 기본 스레드 설정에서 TFLite INT8의 중앙 지연시간은 WISDM 0.0333 ms, PAMAP2 0.1132 ms였다. 실행 경로별 측정값은 다음과 같다. 이 표는 성능 측정 결과이며, 정확도 평가는 실제 데이터셋으로 별도 수행했다.

| 데이터셋 (ms) | Keras predict | Keras 직접 호출 | TFLite FP32 | FP16 | INT8 | INT8 동적* |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| WISDM | 208.7349 | 107.8605 | 0.0488 | 0.0399 | 0.0333 | 0.1921 |
| PAMAP2 | 213.0406 | 165.5518 | 0.5795 | 0.1566 | 0.1132 | 1.8892 |

* INT8 동적 경로는 입력 양자화 등 실행 경로의 부가 작업을 포함한다. 표의 값은 중앙값이며, p95와 메모리 값은 원시 측정 결과와 함께 해석해야 한다.

## 해석과 한계

이 Windows 측정에서는 INT8이 해당 실행 조건에서 가장 낮은 중앙 지연시간을 보였다. Keras `predict`와 직접 호출 사이에도 차이가 있었으므로, Keras와 TFLite의 차이를 양자화 효과만으로 해석할 수는 없다. FP16은 FP32보다 낮은 지연시간을 보였고, INT8 동적 경로는 이 측정에서 FP32보다 길었다.

정확도 결과는 원 학습 데이터 분할과 학습 시 사용한 scaler를 확인하지 못한 상태의 재현 평가 결과다. 따라서 논문 보고 수치와 직접 동등 비교할 수 없으며, 학습 데이터 정보 확인이 필요하다. WISDM은 겹치는 윈도우를 사용하므로 무작위 분할에서 인접 구간이 학습·평가 양쪽에 들어가 성능이 높게 추정될 수 있다. PAMAP2는 파일 경계를 고려한 분할 여부와 Protocol/Optional 파일 구성의 영향도 확인해야 한다. 두 데이터셋의 현재 평가는 단일 기기·세션 조건을 대표하지 않는다.

플랫폼 간 PAMAP2 성능 비교에는 입력 구성 차이도 있다. Windows는 고유 평가 윈도우 494개에서 1,000회 호출을 만들 때 420개 입력을 사용하고 일부 입력을 반복했다. Mac은 494개 윈도우를 순환해 1,000회 호출을 구성했다. 따라서 두 플랫폼의 지연시간 차이를 같은 입력 순서와 빈도의 완전한 통제 비교로 간주하면 안 된다. Windows 결과는 해당 Windows PC와 실행 설정에서 관측한 결과다.
