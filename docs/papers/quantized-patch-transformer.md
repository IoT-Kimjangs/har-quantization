# 양자화 패치 Transformer 논문 정리

센서 데이터를 패치로 묶어 처리하는 Transformer를 만들고, 학습 후 양자화에 따른 정확도·크기·속도 변화를 비교한 논문입니다. 우리 팀이 분석하고 재현할 구체적인 실험 대상입니다.

원문: *Edge efficient human activity recognition using a quantized patch based transformer*, Scientific Reports, 2026, 16, 33293. [DOI 및 원문](https://doi.org/10.1038/s41598-026-62744-4). [저자 공개 코드](https://github.com/AASIFRASHIDKHANDAY/PATCH-BASED-TRANSFORMER-WITH-QUANTIZATION). 아래 수치는 원 논문의 보고값이며 우리 측정 결과가 아닙니다. 쪽수는 PDF에 인쇄된 번호 기준입니다.

## 해결하려는 문제

사람의 행동을 잘 알아맞히는 모델도 작은 기기에 올리기에는 크거나 느릴 수 있습니다. 저자들은 센서 시계열을 묶어 처리하는 패치 구조와 숫자 표현을 줄이는 양자화를 결합해 인식 성능과 실행 비용의 관계를 살펴봅니다.

## 윈도우와 패치의 차이

윈도우는 한 번의 예측에 넣는 전체 센서 구간이고, 패치는 그 윈도우 안을 더 작게 나눈 묶음입니다. WISDM은 80개 시점의 x·y·z 3축 값을 입력하고 이를 8개 시점씩 묶어 패치 10개로 처리합니다.

```text
센서 기록 80시점 × 3축
→ Conv1D로 8시점씩 특징 벡터로 변환
→ 패치 10개에 순서 정보 추가
→ Transformer로 패치 사이 관계 학습
→ 전체 특징을 모아 행동 분류
```

패치 임베딩은 단순한 평균 내기가 아니라 학습 가능한 Conv1D 변환입니다. 패치를 너무 작게 만들면 처리할 토큰이 많아지고, 너무 크게 만들면 세부 움직임을 놓칠 수 있습니다. 위치 임베딩은 패치 순서를 알려주며, Transformer 인코더 뒤에는 전체 평균 풀링과 분류기가 붙습니다(7~9쪽, 그림 8).

| 데이터 | 입력 형태 | 선택한 패치 길이 | 인코더 수 |
| --- | --- | ---: | ---: |
| WISDM | 80시점 × 3채널 | 8 | 2 |
| PAMAP2 | 200시점 × 19채널 | 10 | 3 |

이 설정은 저자가 정확도와 지연시간의 균형을 고려해 선택한 값입니다. 모든 조건에서 정확도가 가장 높은 설정이라는 뜻은 아닙니다. 패치와 인코더 수를 바꾼 비교는 15~16쪽 표 11·12에 있습니다.

## 데이터 처리와 실험 조건

- WISDM은 스마트폰 가속도 데이터, PAMAP2는 여러 신체 위치의 센서와 심박 정보를 활용합니다.
- 윈도우는 50% 겹칩니다. WISDM은 길이 80·stride 40, PAMAP2는 길이 200·stride 100입니다.
- 윈도우 단위로 학습·평가 데이터를 80:20 계층 분할하며 고정된 난수 seed를 사용했다고 설명합니다.
- 표준화는 학습 데이터로 맞춘 뒤 평가 데이터에 적용한다고 서술합니다.
- 학습에는 Adam, 초기 학습률 0.001, 최대 40 epoch, early stopping patience 6을 사용합니다. 배치 크기는 WISDM 128, PAMAP2 64입니다.
- 실행 환경은 Intel Xeon Silver 4208 CPU, RAM 64GB, Windows 10 Pro이며 CPU로 배포 가능성을 측정했습니다.

위 조건은 7~10쪽과 표 1에 있습니다. 논문 설명을 코드의 실제 채널 선택·분할·전처리와 대조하는 일도 재현 작업에 포함합니다. 학습 배치 크기와 우리 지연시간 측정의 배치 1을 혼동하지 않습니다.

## 네 가지 TFLite 형태

학습을 마친 뒤 변환하는 PTQ를 사용합니다. 학습 과정에 양자화를 반영하는 QAT와 구분합니다(9~10쪽).

| 형태 | 비교 목적 |
| --- | --- |
| TFLite FP32 | 양자화하지 않은 TFLite 기준 |
| TFLite FP16 | 가중치를 16비트 실수로 표현한 변형 |
| TFLite INT8 동적 | 가중치를 8비트로 저장하는 동적 범위 양자화 |
| TFLite INT8 전체 정수 | 대표 데이터로 가중치·활성값을 정수 형태로 보정한 변형 |

전체 정수 변환에는 학습 데이터에서 최대 300개 윈도우를 표본으로 뽑아 보정했다고 설명합니다. 실제 연산 정밀도와 성능은 지원 연산자·런타임·하드웨어 조건을 함께 확인해야 합니다.

## 논문이 보고한 결과

기준 모델 정확도는 WISDM 96.771%, PAMAP2 98.480%입니다. TFLite INT8 동적 정확도는 각각 96.789%, 98.379%로 보고합니다(11~12쪽 표 2·3·5·6). WISDM은 소폭 높고 PAMAP2는 소폭 낮으므로 모든 양자화에서 정확도가 떨어졌다고 쓰지 않습니다.

| 실행 형태 | WISDM 크기 KB | 지연시간 ms | PAMAP2 크기 KB | 지연시간 ms |
| --- | ---: | ---: | ---: | ---: |
| 원본 TensorFlow/Keras | 2,474.41 | 108.20 | 3,081.14 | 114.60 |
| TFLite FP32 | 295.20 | 0.22 | 995.71 | 0.33 |
| TFLite FP16 | 163.63 | 0.21 | 520.55 | 0.36 |
| TFLite INT8 동적 | 110.05 | 0.86 | 314.27 | 0.26 |
| TFLite INT8 전체 정수 | 116.52 | 9.73 | 325.07 | 2.40 |

출처: 11쪽 표 4, 12쪽 표 7·8.지연시간은 작을수록 빠릅니다. 크기는 논문의 KB 표기를 유지했습니다. 이 표는 파일 크기를 보여 주며 실행 중 피크 RAM을 측정한 표로 해석하지 않습니다.

## 결과를 읽을 때 확인할 지점

### 큰 속도 변화에는 여러 효과가 섞일 수 있음

WISDM에서 원본은 108.20ms, 양자화하지 않은 TFLite FP32도 이미 0.22ms입니다. 표의 반올림된 값으로 계산하면 이 단계에서 약 99.8% 감소합니다.

이 차이를 모두 양자화 효과로 설명할 수는 없습니다. 변환·런타임·호출 방식·타이밍 범위 등도 영향을 줄 수 있습니다. 원 논문의 속도 차이가 각각 무엇 때문에 발생했는지는 동일 조건의 추가 측정이 필요합니다.

### 더 작은 모델이 반드시 빠르지는 않음

WISDM INT8 동적은 110.05KB로 TFLite FP32의 295.20KB보다 작지만, 지연시간은 0.86ms로 0.22ms보다 약 3.9배 큽니다. PAMAP2에서는 반대로 INT8 동적이 FP32보다 빠릅니다. 전체 INT8도 두 데이터에서 모두 FP32보다 느립니다.

이는 이 논문의 해당 실행 환경에서 나온 결과입니다. 다른 기기에서도 같은 순위일지는 재측정해야 합니다.

### 압축률의 기준을 구분해야 함

논문 WISDM의 22.48배 압축은 원본 2,474.41KB와 INT8 동적 110.05KB의 비교입니다. 같은 TFLite 런타임 안에서 FP32 기준으로 비교하면 약 2.68배입니다.

```text
원본 기준: 2,474.41 / 110.05 ≈ 22.48배
TFLite FP32 기준: 295.20 / 110.05 ≈ 2.68배
```

두 계산은 비교 기준이 다릅니다. 우리는 두 기준을 함께 보고하고, 파일 구성 차이까지 확인한 뒤 압축 효과를 해석합니다.

## 한계와 추가 검증

저자는 실제 마이크로컨트롤러·스마트워치가 아니라 Xeon CPU에서 배포 가능성을 평가했다고 명시합니다(10쪽, 15쪽, 18~19쪽). 실제 기기의 지연시간·전력·배터리 성능을 입증한 결과로 쓰지 않습니다.

또한 겹치는 윈도우를 만든 뒤 윈도우 단위로 분할하므로 같은 사람이나 인접·중첩 구간이 학습과 평가에 섞일 수 있습니다. 새 사람에 대한 일반화 성능으로 해석할 때는 주의해야 합니다. 이것은 검증할 위험 요소이며 정확도 수치 전체가 무효라는 결론은 아닙니다.
