# 확장·응용 실험 계획

원인 분석(확장)을 중심으로 하고, 팀원 휴대폰 데이터 평가(응용)를 더합니다. 12/1 발표 후 진행할 계획입니다. 아직 실행하지 않았으며, 결과가 나오기 전까지 보고서·발표에서 원인을 단정하지 않습니다.

## 확장: 양자화 모델이 느려진 원인 분석

### 왜 하는가

48개 조건 측정에서 파일 크기와 추론시간이 따로 움직였지만, 그 원인은 확인하지 않았습니다. 이번 확장은 실험량을 늘리기보다 이 질문에 답하는 것이 목표입니다. 세 실험을 모두 성공시키기보다 원인 하나라도 근거로 확인하는 것을 우선합니다.

설명할 현상은 [통합 결과](../results/platform-integration-draft/effects.csv)의 다음 값입니다. 모두 같은 플랫폼·스레드의 TFLite FP32 대비 중앙 지연시간입니다.

| 현상 | Mac | Windows |
| --- | --- | --- |
| WISDM INT8 입출력, 기본 설정 | 1.55배 느림 | 3.94배 느림 |
| WISDM FP16, 기본 설정 → 연산 스레드 1 | 0.8% 증가 → 0.4% 증가 | 18.2% 단축 → 206.2% 증가 |
| WISDM 동적 INT8, 기본 설정 | 31.0% 단축 | 31.8% 단축 |

느려짐과 역전은 Windows에서 크게 나타났으므로 원인 분석에는 처음부터 Windows를 포함합니다.

### 실험

새 모델 학습, 새 데이터 다운로드, 장비 구매는 하지 않습니다. 기존 저장 모델·전처리 배열·측정 규약(배치 1, 워밍업 50회, 측정 1,000회, 조건마다 새 프로세스)을 그대로 사용합니다.

| 번호 | 실험 | 확인할 질문 | 준비 |
| --- | --- | --- | --- |
| 1 | 입출력 변환 비용 분리 | INT8 입출력 모델의 느려짐 중 입력 양자화·출력 복원 비용이 얼마인가 | 기존 INT8 입출력과 같은 보정 300개로 변환하되 입출력만 float32로 둔 모델을 추가 |
| 2 | 연산별 시간 | 어느 연산이 시간을 차지하는가, 남은 `DEQUANTIZE → NEG → QUANTIZE` 경로가 원인인가 | TFLite 연산별 프로파일링 도구가 두 OS에서 동작하는지 먼저 확인 |
| 3 | 기본 CPU 가속 켜고 끄기 | 형식마다 XNNPACK 적용 여부가 달라 순위·스레드 효과가 바뀌는가 | `Interpreter(experimental_op_resolver_type=OpResolverType.BUILTIN_WITHOUT_DEFAULT_DELEGATES)`와 기본값 비교. `ai-edge-litert` 2.3.0에서 옵션 존재 확인 |

실험 1·3은 기존 측정 스크립트에 옵션을 더하는 수준이라 먼저 진행합니다. 실험 2는 1·3으로 설명되지 않는 조건에만 시도합니다.

## 응용: 팀원 휴대폰 데이터로 오프라인 평가

### 왜 하는가

공개 데이터 평가는 구간 단위 분할이라 같은 사람이 학습·평가에 함께 들어 있습니다. 학습에 없던 사람의 휴대폰 데이터로 저장 모델과 양자화 모델을 평가해, 새 사람 데이터에서 정확도가 얼마나 달라지는지와 양자화 모델이 FP32와 같은 답을 내는지를 확인합니다. 녹화한 데이터를 노트북에서 평가하는 오프라인 평가이며 실시간 서비스가 아닙니다.

### 수집

| 항목 | 기준 |
| --- | --- |
| 기기 | 팀원 3명의 개인 휴대폰, 새 장비 없음 |
| 기록 앱 | 가속도 X·Y·Z와 시각을 CSV로 내보내는 무료 앱(예: phyphox) |
| 행동 | WISDM 6개 중 걷기·서 있기·앉기는 필수, 조깅·계단 오르기·내리기는 안전한 장소에서 가능하면 |
| 길이 | 사람·행동마다 2분 이상, 행동별로 따로 녹화해 파일 이름으로 라벨 지정 |
| 휴대폰 위치 | WISDM 수집 위치와 맞춰 바지 주머니. 원 데이터 설명을 수집 전 다시 확인 |
| 개인정보 | 가속도와 행동 라벨만 사용. 원본 CSV는 Git에 올리지 않고 집계 결과만 기록 |

### 전처리와 평가

- 기록을 WISDM 명시 주기 20Hz로 다시 샘플링하고, 단위와 축 방향이 WISDM 원본 값 범위와 맞는지 먼저 비교합니다.
- 80시점 구간을 만들고, 기존 WISDM 학습 구간으로 계산한 scaler를 그대로 적용합니다. 휴대폰 데이터로 scaler를 다시 맞추지 않습니다.
- Keras 원본, TFLite FP32, 동적 INT8, INT8 입출력에 같은 구간을 넣어 정확도·Macro-F1·혼동행렬과 FP32 대비 예측 일치율을 계산합니다.
- 정확도가 크게 떨어져도 결과로 보고합니다. 원인 후보(휴대폰 위치, 기종, 샘플링 차이, 사람 차이)를 구분해 적고 모델을 다시 학습하지 않습니다.

## 진행 순서

| 단계 | 기간 | 범위 | 담당 |
| --- | --- | --- | --- |
| 확장 소규모 검증 | 12/1–12/2 | WISDM × Mac × TFLite 4종 × 스레드 2종, 실험 1·3 스크립트 작성과 시험 실행 | 서진정 |
| 확장 핵심 확인 | 12/2–12/3 | 같은 스크립트를 WISDM × Windows에서 실행 | 장은성 |
| 진행 점검 | 12/5 | 원인 분석 진행을 보고 응용 실험 진행 여부 결정 | 전원 |
| 응용 수집·평가 | 12/5–12/10 | 휴대폰 데이터 수집(전원), 전처리·평가 스크립트 | 서진정·장은성 |
| 확장 마무리 | 12/5–12/10 | 설명된 경향이 PAMAP2에서도 유지되는지 확인, 설명되지 않은 조건에 실험 2 | 서진정·장은성 |
| 정리 | 12/10–12/13 | 두 결과로 환경별 양자화 선택 가이드와 한계를 보고서에 반영 | 김가은 |

12/4 보고서 초안에는 그때까지 확인한 결과만 넣고, 진행 중인 항목은 진행 중이라고 적습니다. 12/5 점검에서 원인 분석이 늦어지면 응용은 하지 않고 원인 분석을 끝내는 데 집중합니다.

## 결과 해석 기준

- 휴대폰 데이터 평가는 팀원 3명의 소규모 데이터이므로 일반 사용자 성능으로 일반화하지 않습니다.
- 노트북 CPU 두 대의 결과이며 MCU·스마트폰 등 실제 IoT 기기 성능으로 일반화하지 않습니다.
- 가속을 끈 조건은 원인 확인용 비교이며 권장 실행 설정이 아닙니다.
- 원인이 확인되지 않으면 "확인한 범위에서 원인이 아니었다"로 기록합니다.
- 새 결과는 기존 48개 조건 결과와 다른 폴더에 저장하고, 실행 명령·환경·모델 해시를 함께 남깁니다.

## 최종 산출물

- 실험별 결과 폴더와 요약 문서(휴대폰 원본 데이터 제외)
- 환경별 양자화 선택 가이드: 원인 분석과 휴대폰 데이터 평가 결과를 바탕으로 지연시간·파일 크기·입출력 형식 조건별로 어떤 형식을 먼저 측정해 볼지 정리한 표. 측정 없이 고르는 규칙이 아니라 우선 측정 순서를 제안합니다.
