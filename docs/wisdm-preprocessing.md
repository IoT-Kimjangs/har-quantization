# WISDM 분할과 표준화 기준 재계산

## 무엇을 확인했는가?

저자 공개 저장소의 기준 커밋 `90eb53deec3ff166fa0f1e08211d8d9d1770411d`에서 WISDM 기준 노트북과 배포 파일 목록을 확인했습니다. 학습 때 사용한 scaler, 평균·표준편차, 학습·평가 배열과 분할 인덱스 파일은 찾지 못했습니다. 노트북은 표준화한 배열을 저장하는 코드를 포함하지만 그 결과 파일은 공개 저장소에 포함돼 있지 않습니다.

저장 모델의 구성에서도 입력용 `Normalization` 레이어는 없습니다. `LayerNormalization`은 Transformer 내부 연산이며 원시 가속도를 전처리하는 `StandardScaler`와 다릅니다. 모델 파일만 불러왔다고 입력 표준화 기준까지 확보된 것은 아닙니다.

따라서 원본 데이터와 공개 코드의 설정으로 분할·표준화 통계를 **재계산**했습니다. 이 통계가 배포된 모델의 실제 학습 때 사용한 통계와 일치하는지는 검증할 자료가 없습니다. 기록의 `matches_saved_model_training_statistics`는 `unverified`로 유지합니다.

## 공개 코드의 처리 순서

1. 원본 텍스트를 한 줄씩 읽고 행 끝의 세미콜론을 제거합니다. 필드가 6개가 아니면 건너뜁니다.
2. 타임스탬프·X·Y·Z를 숫자로 바꾼 뒤 결측 행, 타임스탬프가 0 이하인 행, 지정한 6종 외 행동을 제외합니다.
3. 사용자 번호는 문자열로 유지한 채 사용자·타임스탬프로 정렬합니다. 문자열 `"10"`과 `"2"`의 순서는 숫자 정렬과 다르므로 임의로 숫자형으로 바꾸지 않습니다.
4. 사용자별로 X·Y·Z를 `float32`로 바꾼 뒤 길이 80, 이동 간격 40으로 구간을 만듭니다.
5. 구간의 행동은 80개 시점의 최빈 행동으로 정합니다. 동률이면 가장 작은 행동 인덱스를 선택합니다.
6. 구간을 행동 라벨로 층화해 80:20으로 무작위 분할합니다. `random_state=42`를 사용합니다. 사용자 단위 분할은 아닙니다.
7. 학습 구간을 `(학습 구간 수 × 80, 3)`으로 펼쳐 `StandardScaler.fit_transform()`을 적용합니다. 평가 구간에는 같은 scaler의 `transform()`만 적용합니다.

예측과 모델 학습은 실행하지 않았습니다. 전체 노트북을 실행하지 않고 전처리에 필요한 동작만 별도 코드로 구현했습니다. 비유한 숫자를 발견하면 멈추는 검사도 추가했으며 현재 원본에서는 문제가 없었습니다.

## 직접 재계산하는 방법

먼저 [원본 데이터 준비](wisdm-data.md)를 완료하고 Python 의존성을 설치합니다. Mac 환경 의존성은 PR #4, 원본 준비 코드는 PR #6에 있습니다.

```bash
.venv/bin/python scripts/prepare_wisdm_preprocessing.py
```

설정과 원본 파일 해시를 확인한 뒤 `data/processed/wisdm-author-code/`에 아래 파일을 저장합니다. 모두 로컬 산출물이며 Git에서 제외됩니다.

| 파일 | 용도 |
| --- | --- |
| `X_train_s.npy`, `X_test_s.npy` | 표준화한 학습·평가 입력 |
| `y_train.npy`, `y_test.npy` | 같은 순서의 정답 행동 인덱스 |
| `scaler.json` | X·Y·Z 순서의 평균·분산·표준편차와 출처 구분 |
| `train_window_ids.npy`, `test_window_ids.npy` | 전체 구간 중 각 분할이 사용하는 구간 번호 |
| `window_users.npy`, `window_starts.npy` | 전체 구간의 사용자와 사용자별 정렬 데이터에서의 시작 위치 |
| `preprocessing-summary.json` | 실행 버전·집계·검증 결과·산출물 해시 |

기존 산출물과 결과가 다르면 덮어쓰지 않고 멈춥니다. 원본과 실행 버전·설정을 먼저 비교해야 합니다. 같은 환경에서 재실행해 산출물 해시가 동일한 것을 확인했습니다.

[재현 설정](../configs/wisdm-preprocessing.json)에는 기준 노트북 해시와 조건을 기록했습니다. [Mac ARM64 실행 기록](../results/data/wisdm-preprocessing-macos-arm64.json)은 이번 실행 결과의 스냅샷입니다. 다른 환경의 결과와 같은 것으로 가정하지 않습니다.

## 이번 실행 결과

Python 3.12.14, NumPy 2.5.4, pandas 2.3.3, scikit-learn 1.9.1에서 확인했습니다.

| 항목 | 결과 |
| --- | ---: |
| 정제 조건을 통과한 원본 행 | 1,073,623 |
| 전체 구간 | 26,786 |
| 학습 입력 형태 | `(21428, 80, 3)` |
| 평가 입력 형태 | `(5358, 80, 3)` |
| 입력 자료형 | `float32` |

표준화는 축마다 아래 계산을 적용합니다. 아래 표는 읽기 쉽게 반올림했으며 실행에는 JSON의 전체 정밀도 통계를 사용합니다.

```text
표준화 값 = (원래 값 - 학습 쪽 평균) / 학습 쪽 표준편차
```

| 축 | 평균 | 표준편차 |
| --- | ---: | ---: |
| X | 0.681081 | 6.913074 |
| Y | 7.312940 | 6.735416 |
| Z | 0.409828 | 4.789206 |

통계는 학습 구간의 모든 시점을 대상으로 계산하므로 겹치는 구간에 속한 원본 시점은 여러 번 반영됩니다. 평균·분산을 별도 NumPy 계산과 비교했고, 평가 입력 변환도 같은 식의 수동 계산과 비교해 통과했습니다. 구간 번호가 학습·평가에 중복되거나 누락되지 않는 것과 모든 출력이 유한한 값인 것도 확인했습니다.

## 결과를 해석할 때 구분할 점

- **서로 다른 구간 번호여도 원본 시점을 공유할 수 있습니다.** 길이 80, 이동 간격 40으로 구간을 만든 뒤 무작위 분할하므로 인접 구간은 50% 겹칩니다. 이번 실행에서는 학습·평가를 가로지르는 인접 구간 쌍이 8,563개였고, 사용자 36명 모두 양쪽에 등장했습니다. 새로운 사용자에 대한 일반화 성능을 검증하는 분할이 아닙니다.
- **행동 전환과 시간 간격을 추가로 나누지 않습니다.** 원본 코드는 사용자 단위로 정렬한 시계열에서 구간을 만들며, 행동이 섞인 구간은 최빈값으로 라벨을 정합니다. 이번에는 행동이 섞인 구간이 713개였습니다. 시간 간격 이상을 기준으로 구간을 끊는 처리를 임의로 추가하지 않았습니다.
- **추후 검증용 부분집합도 scaler 계산에 들어갑니다.** 원본 모델 학습 코드는 바깥 학습 80%를 먼저 표준화한 다음 `validation_split=0.15`를 사용합니다. 이번에는 이 전처리 범위를 따랐고, 모델 학습이나 검증 부분집합 생성은 진행하지 않았습니다.
- **저장 모델과 통계의 일치는 미확인입니다.** 원본 학습 환경 버전, 정확한 분할 결과, scaler를 대조할 수 없습니다. 공개 코드 재계산 결과로 시험 추론은 할 수 있지만 이를 논문 정확도나 원본 학습 조건의 완전한 재현으로 표현하지 않습니다.

다음 단계는 재계산한 평가 샘플 하나를 저장 모델에 넣어 입출력이 정상적으로 연결되는지 확인하는 것입니다. 실제 정답과 예측을 함께 기록하고, 위 한계를 유지합니다. 사용자 단위 분리 실험은 별도로 설계합니다.
